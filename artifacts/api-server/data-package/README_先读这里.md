## 3. 来源选择为何这样安排

**实时可更新层：**

- [arXiv API](https://info.arxiv.org/help/api/user-manual.html)：不用密钥。用摘要关键词和统一的 cs.AI/cs.LG/cs.CL/cs.CV 类别查询。它测量研究关注度，不是招聘量。不能把 RAG 论文增长百分比改名为 RAG 岗位增长百分比。
- [Arbeitnow 公共 API](https://www.arbeitnow.com/blog/job-board-api)：已成功取得可更新招聘样本，适合演示采集和技能提取。偏欧洲，当前样本发布日期为 2026-10-16 至 2026-10-20；前几页存在排序、地域、语言与存续偏差。这里只使用“样本提及频数”，不计算历史招聘增长。

**马来西亚相关层：**

- [TalentCorp MyCOL](https://www.talentcorp.com.my/mycol/)：用本地紧缺职业清单证明选题与当地相关。2024/2025 是统计/报告期，不能因为今天访问就称为“2026 年岗位增长”。本次已下载完整官方 PDF，并视觉核对 Table 7 全部 66 个代码（实体 PDF 页 44–45，印刷页 85–87）。保存 11 条相关职业记录及完整代码清单，不宣称批量导入全部报告。职业是否列入该版依据完整代码清单判断；未列入不等于没有需求。
- [DOSM 技能相关就业不足](https://data.gov.my/data-catalogue/lfs_qtr_sru_age)：官方可更新聚合数据，可用于问题背景图。它不衡量“AI 导致失业”，也不用于判断某个个人是否应被招聘。

**岗位、升降和 SDG：**

- [O*NET](https://www.onetcenter.org/database.html)：核验职业名称及职业背景。JSON 中的技能程度与职业方向为团队 MVP 设计，不冒充 O*NET 原始评分。
- [BLS Table 1.2](https://www.bls.gov/emp/tables/occupational-projections-and-characteristics.htm)：美国长期职业预测；是补充升降证据，不能转写成马来西亚预测，也不能据此声称 Excel 技能已被 AI 替代。当前版本保存 2025–2035 表，别与网上仍可见的 2024–2034 旧版本混用。
- [UN SDGs](https://sdgs.un.org/goals)：使用 4.3、4.4、8.2、8.5、9.1、9.5、10.2、10.3、16.6 等目标解释职业路径的潜在贡献，不表示 UN 认证或已测得社会影响。

**未作为主数据源的方案：**

- [Adzuna](https://developer.adzuna.com/overview) 需要 `app_id` 和 `app_key`；本包没有调用，也没有假设免费 API 支持马来西亚 `my`。取得团队凭据并核实国家覆盖后再接入。
- Kaggle 可以补充历史分析，但静态问卷、旧岗位样本不一定有可比时间窗口、可再分发许可或当前招聘信号。初赛用已验证 API 更容易讲清刷新链路。
- ESCO 是可扩充知识库的候选；本包采用 O*NET，不声称已下载完整 ESCO。

## 4. 统计与匹配方法

**时间窗：**采集日期 2026-10-20；为减少近期索引延迟，排除最近 7 天。前期为 `[2026-04-16, 2026-07-15)`，后期为 `[2026-07-15, 2026-10-13)`，两者各 90 天。区间使用 UTC，右端不包含。

- 原始研究增长：`(后期主题计数 / 前期主题计数 - 1) × 100%`。
- 主题占比：主题计数除以该窗口四个类别的总体计数。主题重叠，不得将各主题计数相加当作去重论文总量。
- 匹配用动量：`后期主题占比 / 前期主题占比 - 1`。前期为零则不可计算；任一期少于 10 则标记低计数，不强推结论。
- 此版本共同总体为前期 36,718、后期 36,804。类别、关键词、预印本收录和学期变化仍可能影响结果；没有做预测效度验证或因果推断。
- 招聘命中使用英文词边界和可维护同义词字典。它是弱标签：例如文本提到某技术，不等于岗位要求熟练掌握；德语描述可能漏检，短词可能误检。

**匹配分数是排序指标，不是“获得工作的概率”：**

1. 技能适配 `F`：对岗位每项要求计算 `min(已有程度/目标程度, 1)`，按配置权重取平均。
2. 研究动量 `R`：每个岗位关联主题的占比相对变化率限制在 `[-1,1]` 后转为 `[0,1]`，取平均；缺数据用中性 0.5，并保留缺失标记。未采用反馈提出的 0.35 下限，也未进行未经验证的季节校正。
3. 招聘样本支持 `J`：主题技能提及数除以全部 20 项技能中最大提及数，再按岗位关联主题取平均。此值仅表示该欧洲样本内的相对支持。
4. `S = 0.7R + 0.3J`。
5. `Score = 100 × ((1-w)F + wS)`。温和采用 `w=0.20`，快速采用 `w=0.40`。

这些权重是**团队可解释的演示假设**，不是训练获得、专家共识或真实预测概率。MyCOL 作为本地证据标签展示，不对未列入紧缺清单或仅宽泛映射的职业扣分；DOSM 与 BLS 在此版作为背景/长期展望展示，未暗中混入即时匹配分数。

`reports/matching_demo.json` 中的“中性动量对照”固定用户、岗位和招聘样本，仅将研究动量置为中性。真实动量输入会改变分数和部分排序。**中性对照是消融实验，不是第二份真实市场快照。** 现场应分别展示“数据驱动结果”“真实网络刷新”“参数情景”三件事，不把它们混称为实时预测。

## 5. 本地课程与成本

已逐条核对官方/提供方页面，剔除两门已下架 OpenLearn 课程。这里保存课程元数据与链接，没有复制完整课程内容。

- C16：HRD Corp e-LATiH 的 **Future Skills Mapping for Organisations**，页面标为免费，时长 1.5 小时，适合 HR/培训场景。
- C21：**Data Privacy and Protection**，页面价格 RM90，时长 1 小时，付费可选。
- C22：**Using AI to Boost Employee Engagement: Predict Burnout and Improve Retention**，页面价格 RM47，时长 44 分钟，付费可选。

以上价格核对日期为 2026-10-20。**课程在 e-LATiH 出现，不自动代表可由 HRD 基金报销。** 本包所有 `hrd_claimable_status` 均为 `not_verified`；需要按具体项目、雇主与审批条件核实。HRD 报销课程是原文允许的资源例子，并非必须凑够的独立指标。

开源课程免费的是学习材料；托管模型 API、云实验和证书可能收费。DeepLearning.AI 免费视频与付费功能分别标注。Coursera/edX 的两条资源保留报名核实状态，默认路线不依赖“所有课程都能免费 audit”这一假设。

课程时长有 `duration_basis`：提供方明确写明则使用官方时长；其余是团队学习预算估计，不能当作完成整个长课程的保证。路线是入门资源序列，需要另加合成项目练习和能力评估，不能宣称看完短课就满足三级岗位技能。

## 6. 运行方式

解压后进入本文件所在文件夹。Python 3.10+，匹配与验证只用标准库，无需 API 密钥。Windows 环境遇到 Python 证书链问题时，刷新脚本可使用系统 `curl.exe`；不关闭 TLS 验证。

```powershell
python scripts/validate.py
python scripts/match.py
python scripts/match.py --profile SYN-A --scenario moderate
```

验证会生成或覆盖 `reports/validation.json` 和 `reports/matching_demo.json`。默认使用已保存真实缓存，**无需联网即可演示结果**。

更新研究和招聘数据：

```powershell
python scripts/refresh.py --source all --pages 3
python scripts/refresh_malaysia.py
python scripts/validate.py
```

`refresh.py` 默认采用运行当天 UTC 日期，并保留 7 天索引缓冲。arXiv 顺序请求，间隔至少 3.2 秒；网络慢时需几分钟。单个来源完整成功后才替换该来源缓存；失败保留旧数据、输出错误并以非零状态退出。刷新失败时仍可运行 `match.py`，但 UI 必须标明缓存模式、各来源真实采集时间和最近失败状态。

`computed_at` 是派生指标计算时间，不能代替源数据的 `retrieved_at`。刷新后检查 `reports/last_refresh.json`；不同来源可能有不同新鲜度。

岗位/课程/MyCOL/BLS 为人工审阅的版本化知识与外部统计摘录，更新流程见 `DATA_DICTIONARY.md`。不能通过只改日期伪装更新。

## 7. 前端与团队分工

保留原 A/B/C 分工，但设统一 `skill_id`，不让各自再造字段：

- **A：信号层。** 维护 `refresh.py`、查询词、采集状态；显示研究窗口和招聘样本范围。现场提供网络刷新与缓存回退。
- **B：知识及资源。** 维护 `roles.json`、`courses.json`、技能/岗位 SDG 理由；每条新增推荐先有证据链接，再决定是否进入默认结果。
- **C：档案与集成。** 使用 5 个合成档案做一键加载；连接 `rank()`、`pathway()`；展示两种情景与来源侧栏，完成 GitHub 和现场流程。

建议 Streamlit 最小界面包含：合成档案选择、两情景选择、技能雷达、岗位分数与差距、课程步骤及周数、数据来源与时间、缓存/刷新状态。不要增加真实 CV 上传作为初赛依赖。

建议演示顺序：载入 SYN-B → 查看研究主题与招聘样本 → 查看推荐及差距 → 切换情景 → 展示中性动量对照 → 打开真实来源查询 → 执行刷新/展示缓存 → 显示课程路线和 SDG 理由。SYN-C 的架构方向应定位为长期探索，不应因技能相似就断言应届毕业生已符合高级架构师资格。

## 8. 目前边界与最重要风险

数据足以支持**有证据的初赛原型**，不足以支持“准确预测马来西亚未来各技能就业增长”的产品声明。最难的缺口是马来西亚细粒度、可连续采样的岗位技能需求：MyCOL 给紧缺职业、DOSM 给总体背景，欧洲招聘源不能替代本地市场。后续可接入已获授权且国家覆盖明确的招聘 API，定期保存同样范围的快照，并评估岗位抽取和匹配质量。

AI 披露：数据整理及初版代码由 Codex 辅助完成；运行时的采集、匹配、课程选择不调用语言模型。若团队后续接 LLM，请按 Domain 要求记录实际供应商/模型标识和用途，并限制它只解释已有记录，不允许生成未在知识库核验的岗位、课程或统计。
